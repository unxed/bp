# Safe Pascal — спецификация v0.5

> **Better Pascal (v0.6):** библиотека разнесена по слоям. Упоминания `safe.pas` и `SafeThreads` ниже читать как `safe/*.inc` (слой safe), `ext/*.inc` и `ext/bpthreads.pas` (слой ext); подключается `unit BP` (всё сразу, первым в программе, последним в остальных юнитах) или `unit Safe` (только слой safe). См. корневой README.


Безопасный по умолчанию Free Pascal. Не форк, не новый синтаксис: **один файл `safe.pas` и одна строка
`uses Safe` в каждом модуле**. Работает на штатном FPC 3.2+ без опций компилятора.

Документ написан так, чтобы его можно было целиком приложить к промпту: модель, которая пишет код
строго по §0, пишет код по Safe Pascal. Остальные разделы объясняют §0 и задают API.

Перенос всего этого (или идей отсюда) в FPC/Lazarus в любом виде **приветствуется**: от нас для этого
ничего не требуется, и от FPC для работы Safe Pascal тоже.
Лицензия: MIT (`LICENSE`, заголовок `safe.pas`).

Версии и что проверено на каких целях: §2 (таблица) и §17 (история).

## §0. Карточка правил (для модели и для ревьюера)

```
ЗАГОЛОВОК КАЖДОГО МОДУЛЯ
  {$mode objfpc}{$H+}                 // так Lazarus и так пишет в новый модуль
  uses ..., SysUtils, ..., Safe;      // Safe — ПОСЛЕДНИМ в uses (S7)

СТРОКИ                                 (UTF-8 everywhere)
  Единственный строковый тип — String, всегда UTF-8.
  Length(S) и S[i] — БАЙТЫ. Pos/Copy/Delete на байтовых индексах корректны.
  Символы нужны редко: for Ch in CodePoints(S) (Ch: String), CPLength(S).
  UnicodeString/WideString/ShortString/PChar — только на границе с ОС, в unsafe-коде.
  Бинарные данные — specialize TArray<Byte>, не String.

ДАННЫЕ И ВРЕМЯ ЖИЗНИ                   (выбираем по структуре данных, не по проекту)
  1. По умолчанию — значения: record, String, specialize TArray<T>. Проблем со временем жизни нет.
  2. Объект с одним владельцем        → specialize TOwned<TFoo>.Own(TFoo.Create(...))
  3. Объект с несколькими владельцами → specialize TShared<TFoo>.Share(TFoo.Create(...))
     обратная ссылка / кэш / наблюдатель → TWeak<TFoo> из Shared.Weak (циклы Shared запрещены)
  4. Много объектов одной судьбы       → TArena: A := TArena.Create; X := A.Adopt(TFoo.Create) as TFoo
  5. COM-интерфейсы (TInterfacedObject) — готовый Shared; объект держим ТОЛЬКО через интерфейс.

ССЫЛКИ
  Поля владеют, локальные одалживают:
    поле/глобальная переменная класса-типа  → TOwned/TShared/TWeak/интерфейс
    параметр/локальная переменная класса-типа → заём (borrow), живёт не дольше вызова
    поле-заём допустимо только с комментарием  // borrow: <кто владеет>   (S5)
  Результат TFoo.Create сразу уходит в Own/Share/Adopt, в интерфейс или в raise (S6).
  Нет .Free, FreeAndNil, Destroy, GetMem, New, Dispose, Move, FillChar, Pointer, ^T, @ (S1–S4).
  Вместо FillChar(R, SizeOf(R), 0) — R := Default(TRec).
  Слайс-параметр — открытый массив: procedure Parse(const Data: array of Byte); Parse(Buf[10..20]).
    Хранимый слайс — specialize TSlice<T> (как в Go: массив + начало + длина, с проверкой границ).

ОШИБКИ И ОТСУТСТВИЕ
  Нет Option и магических nil: «может не быть» = function TryX(...; out V): Boolean.
  Нарушение правил безопасности в рантайме = исключение ESafety, никогда не UB.

ТИПЫ-СУММЫ И ПАРАМЕТРЫ                 (§16; enum и match из Rust без новой библиотеки)
  Вариантная запись с тегом: TShape = record case Kind: TShapeKind of skCircle: (R: Double); skRect: (W, H: Double); end;
  Создаётся только функцией-конструктором (Circle(2.0)); вариантное поле читается только в ветке своего тега
  внутри case S.Kind of; case по перечислению перечисляет ВСЕ значения и не имеет else (S13).
  String и другие управляемые типы — в общей части записи (в вариантной FPC их не допускает).
  Параметры — const по умолчанию; var/out — только когда вызывающий должен увидеть изменение (S14).

ОЧИСТКА И ТЕСТЫ                        (§5; идея из Zig)
  Не-память (дескриптор, режим терминала, замок): D := TDefer.Call(@Self.Close) — вызовется при выходе из области
  видимости и при исключении; D.Cancel — «успех, вызывать не нужно».
  Конец теста: SafeCheckNoLeaks — живых объектов под владением нет, в TDefer ничего не подавлено (R5).

СТАРЫЙ СТИЛЬ                           (§12)
  object, New(P, Init(...)), Dispose(P, Done), ShortString/String[N], записи через Move: концепцией не покрыты.
  Пока не решено (расширить Safe на object / перейти на class), такой код — // UNSAFE-UNIT: с безопасным фасадом.

ЦЕЛИ                                   (§2, таблица проверенного)
  Linux (x86_64, i386, aarch64): по умолчанию статический бинарник без libc, работает на любом дистрибутиве;
  потоки — SafeThreads. FFI к C-библиотекам и libc — только с -dSAFE_LIBC (§18).
  DOS: потоков нет, TGroup.Go бросает R8. Windows: собирается, запуск не проверен.

UNSAFE
  Небезопасное пишется полными именами (System.GetMem, SysUtils.FreeAndNil, System.Pointer)
  и строкой выше — комментарий  // UNSAFE: <почему это безопасно>.
  Целый небезопасный модуль: лежит в unsafe/, первая строка  // UNSAFE-UNIT: <зачем>.
  Сырые указатели не выходят из unsafe-кода в безопасный API.

ГОРУТИНЫ                               (§14; «не общайтесь через общую память — делитесь памятью, общаясь»)
  G := TGroup.Create;  G.Go(TWorker.Create(Args, Ch));  ...  G.Wait;   // группа ждёт всех и при выходе из области
  Задача = класс-наследник TTask: аргументы — поля из конструктора, код — Run.  Простой случай: G.Go(@Proc).
  Поля задачи: значения, String, TArray, TChan, TShared, TOwned через Move. Не заёмы, не общие объекты (S11).
  Каналы: Ch := specialize TChan<T>.Create(Cap); Send / Recv(out V): Boolean / TryRecv / Close; for V in Ch.
  select: case Select([A.Sel, B.Sel, Done], TimeoutMs) of ... — затем TryRecv; -1 = таймаут.
  Отмена: G.Cancel → закрывается Done; в задаче — Cancelled или Done в Select. Ошибка задачи → G.Wait бросает R7.
  В ФАЙЛЕ ПРОГРАММЫ первым модулем  uses SafeThreads, ...  (на Linux — свои потоки без libc, §18;
  с -dSAFE_LIBC и на других Unix — cthreads). Без него Go → R8.

FFI                                    (§13; как cgo)
  external-объявления — только в модуле обвязки (// UNSAFE-UNIT:), наружу — безопасный фасад.
  String → C: System.PChar(S) на время вызова. C → String: присваивание (копия).
  Память/дескриптор от C — сразу в TOwned<TCResource> с парной функцией освобождения.
  Обратный вызов из C: cdecl, исключения наружу не выпускать (try..except внутри).
```

## §1. Идея в одном абзаце

В FPC уже есть почти всё: строки с подсчётом ссылок и кодировкой, динамические массивы, записи
с автоматической финализацией, интерфейсы с атомарным счётчиком, проверки диапазонов,
исключения с гарантированной финализацией. Не хватает трёх вещей: **(1)** правильных умолчаний
(UTF-8), **(2)** пары тонких обёрток для объектов и **(3)** способа сделать опасное заметным.
Safe Pascal даёт все три в одном модуле, а опасные примитивы «отравляет» затенением имён:
модуль `Safe`, стоящий последним в `uses`, объявляет одноимённые символы, и компилятор сам
отклоняет `GetMem(...)` с сообщением, где написано, что делать вместо. Полное имя
(`System.GetMem`) затенение обходит — это и есть явный opt-in в unsafe, видимый грепом.

## §2. Подключение

| Способ | Что сделать | Аналог в индустрии |
|---|---|---|
| **Файл рядом** (основной) | положить `safe.pas` в папку с исходниками | SQLite amalgamation, stb, vendoring в Go |
| Общая копия | одна строка `-Fu/путь/к/safe-pascal` в `~/.fpc.cfg` | `GOPATH` |
| Lazarus | пакет в OPM (план, §11) | npm / cargo |
| Апстрим | модуль в поставке FPC — ничего не делать | `std` |

FPC ищет модули в папке компилируемого исходника, поэтому «файл рядом» не требует опций.
Ключи `-Fa`, `-Mobjfpc`, `-Sh`, `-FcUTF8` не нужны:

- UTF-8 включается в `initialization` модуля `Safe`, а он есть в `uses` каждого модуля → гарантированно
  отрабатывает до основной программы. `-Fa` (который к тому же действует только на программы) не нужен.
- `{$mode objfpc}{$H+}` Lazarus и так вставляет в каждый новый модуль.
- `-FcUTF8` не нужен и **вреден**: литералы без `{$codepage}` хранятся как есть (байты UTF-8) с кодировкой `CP_ACP`,
  а `CP_ACP` в рантайме = `DefaultSystemCodePage` = UTF-8. Так работает Lazarus. С `-FcUTF8` (и с `{$codepage utf8}`)
  литералы становятся `UnicodeString`, и `Pos('ве', S)` возвращает 0 (проверено, FPC 3.2.2) — не включайте.

`uses Safe` — одновременно импорт и объявление «этот модуль безопасный» (ср. `#![forbid(unsafe_code)]`
в Rust). Модуль без `uses Safe` считается небезопасным и должен быть помечен (§7).

Отключить UTF-8-инициализацию (если приложение само управляет кодировками): `-dSAFE_NO_UTF8`.

Linux по умолчанию собирается без libc (§18): `cwstring` и `cthreads` не нужны, `-dSAFE_NO_CWSTRING` остался только для случая `-dSAFE_LIBC` на статической сборке без libc.

## §3. Строки: UTF-8 everywhere

- `String` = `AnsiString` с `DefaultSystemCodePage = CP_UTF8`. Имена файлов, консоль, `Input/Output` — UTF-8.
  На Unix внутри `Safe` подключён `cwstring`, на Windows включается UTF-8 в консоли.
- Индексы и длины — в байтах (как Go и Rust). UTF-8 самосинхронизируется: поиск подстроки
  по байтам не может найти «половину символа», поэтому `Pos/Copy/Delete/StringReplace` корректны.
- Символ (code point) — тоже `String`: `for Ch in CodePoints(S) do if Ch = 'ё' then ...`.
  Битый или обрезанный байт — отдельный «символ»; обход не зацикливается и ничего не теряет.
- Конверсия в UTF-16 — только на границе с ОС/библиотекой, в unsafe-коде.
- Известное ограничение: смена регистра на Unix идёт через libc и зависит от локали (`LANG=C` →
  кириллица не меняет регистр).

## §4. Модель владения

Сокращения относительно исходной концепции (и почему):

| Было | Стало | Почему |
|---|---|---|
| `Option<T>` | `TryX(out V): Boolean` | Это родная идиома Паскаля (`TryStrToInt`, `TDictionary.TryGetValue`), ноль нового |
| `Borrow<T>` | обычная ссылка в параметре/локальной | Тип-обёртка не даёт гарантий без borrow checker; правило «поля владеют, локальные одалживают» проверяется линтером |
| `Slice<T>` для параметров | открытый массив `array of T` | Компилятор сам передаёт указатель+длину, проверяет границы при `{$R+}` и **не даёт сохранить** открытый массив — это заём по построению |
| `Slice<T>` для хранения | `TSlice<T>` поверх `TArray<T>` | Динамический массив со счётчиком ссылок: слайс держит массив живым, висячий слайс невозможен. Семантика Go-слайса |
| `Owned<T>` = уникальный указатель | `TOwned<T>` на счётчике | см. ниже |
| `GCHeap` | вне MVP (§11) | |
| `unsafe begin end` | полные имена + `// UNSAFE:` | Синтаксис не меняем; полное имя обходит затенение и грепается |

### Почему `TOwned` на счётчике ссылок, а не уникальный

В FPC запись копируется в разных местах по-разному (присваивание, параметр по значению,
временные результаты функций), и операторы `Copy`/`AddRef` управляемых записей не дают
надёжно реализовать перенос владения. Уникальный указатель, скопированный «мимо» оператора,
даёт двойное освобождение. Поэтому:

- `TOwned` и `TShared` устроены одинаково: запись = ссылка на объект + интерфейс-«время жизни».
  Счётчик ведёт сам компилятор (поле-интерфейс в записи), своих операторов нет.
- Случайная копия `TOwned` **не ломает память**: она лишь продлевает жизнь объекта до смерти последней копии.
- Уникальность — контракт, а не механизм: линтер требует, чтобы `TOwned` копировался только через
  `.Move`, а в параметры шёл как `const` (заём) или `var`. При соблюдении контракта уничтожение
  детерминировано и происходит ровно при выходе владельца из области видимости.

Цена — один атомарный инкремент при создании и при `Move`. Это дёшево.

### Таблица выбора

| Данные | Тип | Уничтожение |
|---|---|---|
| значения, строки, массивы | `record`, `String`, `TArray<T>` | автоматически, как всегда |
| объект одного владельца (файл, сокет, форма-диалог) | `TOwned<T>` | при выходе владельца из области видимости или `Reset` |
| реально разделяемый объект | `TShared<T>` | когда исчезла последняя ссылка |
| обратная ссылка, кэш, подписчик | `TWeak<T>` | не владеет; `TryLock` безопасно падает, если объекта нет |
| дерево/граф/AST/результаты разбора | `TArena` | все разом: `FreeAll` или выход арены из области видимости |
| ресурс ОС | класс-обёртка с деструктором + `TOwned` | RAII: деструктор закрывает дескриптор |

Внутри арены объекты ссылаются друг на друга сырыми ссылками с пометкой `// borrow: arena`.

## §5. API (`safe.pas`)

В режиме objfpc обобщения требуют `specialize`; принято объявлять синонимы:
`type TFooBox = specialize TOwned<TFoo>;`.

```pascal
ESafety = class(Exception);              // нарушение безопасности в рантайме

generic TOwned<T: class> = record
  class function Own(AObj: T): TOwned; static; // забрать во владение; nil → пустой
  function Get: T;                        // заём; пустой → ESafety (R1)
  function TryGet(out AObj: T): Boolean;
  function IsEmpty: Boolean;
  function Move: TOwned;                  // B := A.Move; A пуст
  procedure Reset;                        // уничтожить сейчас (если владелец последний)
end;

generic TShared<T: class> = record
  class function Share(AObj: T): TShared; static;
  function Get: T; function TryGet(out AObj: T): Boolean; function IsEmpty: Boolean;
  procedure Reset;
  function Weak: specialize TWeak<T>;
  function TryLock(const W: specialize TWeak<T>): Boolean; // Self := сильная ссылка, если жив
end;

generic TWeak<T: class> = record
  function IsAlive: Boolean;
  procedure Reset;
end;

generic TSlice<T> = record                // хранимый слайс (Go-семантика: запись видна во всех слайсах)
  class function From(const A: specialize TArray<T>): TSlice; static;
  function Sub(AStart, ALen: SizeInt): TSlice;  // за границами → ESafety (R2)
  function Len: SizeInt;
  function ToArray: specialize TArray<T>;       // копия
  property Items[I: SizeInt]: T; default;      // 0-based, за границами → ESafety (R2)
end;

TArena = record
  class function Create: TArena; static;
  function Adopt(AObj: TObject): TObject;  // результат — заём: X := A.Adopt(TFoo.Create) as TFoo
  procedure FreeAll;                       // уничтожает в обратном порядке
  function Count: SizeInt;
end;

function CodePoints(const S: String): TCodePointEnumerator;  // for Ch in CodePoints(S)
function CPLength(const S: String): SizeInt;

TDefer = record                          // идея из Zig: defer. Сторож области видимости (в том числе при исключении)
  class function Call(AProc: TSafeDeferProc): TDefer; static;  // D := TDefer.Call(@Self.CloseHandle)
  procedure Cancel;                      // успех: отложенный вызов не нужен
end;                                     // TSafeDeferProc = procedure of object

function SafeLiveCount: LongInt;         // сколько объектов сейчас под владением (Own/Share/Adopt)
procedure SafeCheckNoLeaks;              // в конце теста: живых нет и в TDefer ничего не подавлено, иначе ESafety R5
function SafeDeferFailures: LongInt;     // исключения, подавленные в отложенных вызовах
```

Проверки рантайма (всегда включены, стоят одно сравнение):

| Код | Ситуация |
|---|---|
| R1 | `Get` у пустого `TOwned/TShared` (после `Move`/`Reset`) |
| R2 | индекс или `Sub` вне границ `TSlice` |
| R3 | `Own/Share/Adopt` объекта `TInterfacedObject` (им владеет счётчик интерфейса — держите его через интерфейс) |
| R4 | `TArena` не создана (`TArena.Create`) |
| R5 | `SafeCheckNoLeaks` в конце теста: остались живые объекты под владением, подавленные исключения в `TDefer` или ошибки задач, не забранные `TGroup.Wait` |
| R6 | `Send` в закрытый канал, повторный `Close` (как panic в Go) |
| R7 | задача группы упала: `TGroup.Wait` бросает с исходным классом и текстом исключения |
| R8 | `TGroup.Go` без потоков: в программе нет `SafeThreads` (или `cthreads`), либо цель без потоков (DOS) |

Потокобезопасность v0.1: счётчики атомарны, поэтому `TShared` можно копировать между потоками;
`TWeak.TryLock` из разных потоков одновременно с последним `Reset` — гонка (§11).

## §6. Чем обеспечивается каждое правило

| Правило | Что запрещено | Чем ловится сейчас |
|---|---|---|
| S1 | `GetMem/FreeMem/ReallocMem/AllocMem/New/Dispose` | **компилятор**: затенены типом-заглушкой → ошибка + сообщение `SAFE-S1` |
| S2 | `Move/FillChar` | **компилятор**: то же, `SAFE-S2` |
| S3 | `.Free`, `FreeAndNil`, `.Destroy` | `FreeAndNil` и `.Free` — ошибка компилятора. `.Free` закрыт хелпером `TObject` с методом `Free(const X: SAFE_S3_NoFree_UseTOwnedReset_or_UnsafeDestroy)`: без аргумента вызов не компилируется, а имя типа в сообщении «Found declaration» объясняет правило. `.Destroy` — линтер |
| S4 | `Pointer, PByte, PChar, PAnsiChar, PWideChar`, `^T`, `@`, арифметика указателей | типы — предупреждение `SAFE-S4`; `^T`, `@` — линтер |
| S5 | поле/глобальная переменная класса-типа без `// borrow:` | линтер |
| S6 | `TFoo.Create` не сразу в `Own/Share/Adopt`/интерфейс/`raise` | линтер; рантайм частично (R3) |
| S7 | `Safe` не последний в `uses` | линтер (иначе `FreeAndNil` из SysUtils не затенён, хелпер может быть перекрыт) |
| S8 | unsafe-код без `// UNSAFE:` / модуль без `uses Safe` и без `// UNSAFE-UNIT:` | линтер |
| S9 | `UnicodeString/WideString/ShortString` вне unsafe | линтер |
| S10 | копия `TOwned` не через `.Move`; `TOwned` по значению в параметре | линтер; рантайм безопасен в любом случае (§4) |
| S11 | поле задачи `TTask` — заём или изменяемый объект, доступный другим потокам | линтер |
| S12 | `external` вне модуля `// UNSAFE-UNIT:`; публичный API обвязки с указателями | линтер |
| S13 | `case` по перечислению не перечисляет все значения или имеет `else`; вариантное поле читается вне ветки своего тега (§16) | линтер (FPC 3.2.2 не предупреждает) |
| S14 | параметр без `const`/`var`/`out`; `var`, хотя вызывающему изменение не нужно (§16) | линтер |

Предупреждения превращаются в ошибки одной директивой в модуле `{$WARN SYMBOL_DEPRECATED ERROR}`
или ключом `-Sew` для всего проекта. Режимы миграции: **permissive** — предупреждения;
**strict** — ошибки.

Рекомендуемые проверки FPC для отладочной сборки (в Lazarus — режим сборки Debug):
`-Cr -Co -CR -Sa -gh -gt` (диапазоны, переполнение, проверка объектов, assert, heaptrc, мусор
в локальных переменных). В релизе можно снять `-Cr -Co -CR`; проверки R1–R4 остаются.

## §7. Unsafe

```pascal
// UNSAFE: Buf выделен на Len байт строкой выше и освобождается в finally этой же процедуры
System.GetMem(Buf, Len);
```

- Внутри безопасного модуля: полные имена (`System.GetMem`, `System.Move`, `System.Pointer`,
  `SysUtils.FreeAndNil`, `Obj.Destroy`) и комментарий `// UNSAFE:` строкой выше.
- Целые модули (обвязка WinAPI, терминал, аллокаторы, C-библиотеки): папка `unsafe/`,
  первая строка `// UNSAFE-UNIT: <зачем>`, `uses Safe` можно не подключать.
- Граница: публичный API unsafe-модуля использует только типы из §4–5; сырые указатели наружу не выходят.

## §8. Честная таблица гарантий

| Гарантия | Уровень |
|---|---|
| Нет `GetMem/FreeMem/New/Dispose/Move/FillChar/FreeAndNil` вне unsafe | компилятор |
| Двойное освобождение через `TOwned/TShared/TArena` невозможно | рантайм-конструкция (счётчик) |
| Доступ к пустому владельцу, выход за границы слайса | рантайм (ESafety) |
| Висячий `TSlice`, висячий `TWeak` | невозможны по построению |
| `.Free` вне unsafe | компилятор (ошибка) |
| сырые указатели вне unsafe | компилятор-предупреждение + линтер |
| Заём (параметр/локальная) не переживает владельца | линтер (S5) + программист |
| Отсутствие циклов `TShared` | программист + линтер (эвристика) |
| Объекты арены не используются после `FreeAll` | программист; в отладке `-gh` |

Мы не утверждаем, что это Rust. Мы утверждаем: в безопасном коде нет **синтаксической**
возможности сделать типичные ошибки памяти, а оставшиеся дыры перечислены выше.

## §9. Миграция существующего кода

1. Добавить `Safe` последним в `uses` модуля — получить список предупреждений и ошибок.
2. Ошибки S1/S2 (сырые аллокации) — перенести в unsafe-модули или заменить на `TArray<T>`/`TSlice<T>`.
3. `Create ... try finally Free` → `TOwned`. Поля-объекты с ручным `Free` в деструкторе → поля `TOwned`.
4. Разделяемые объекты → `TShared`, обратные ссылки → `TWeak`.
5. Деревья и временные структуры → `TArena`.
6. Включить strict.

## §10. Пример

```pascal
{$mode objfpc}{$H+}
uses Classes, SysUtils, Safe;

type
  TStringsBox = specialize TOwned<TStringList>;

function CountWords(const FileName: String): SizeInt;
var
  Lines: TStringsBox;
  Line, W: String;
begin
  Lines := TStringsBox.Own(TStringList.Create);
  Lines.Get.LoadFromFile(FileName);     // UTF-8 имя и UTF-8 содержимое
  Result := 0;
  for Line in Lines.Get do
    for W in Line.Split([' ']) do
      if W <> '' then Inc(Result);
end;                                    // список уничтожен здесь, в том числе при исключении
```

## §12. Что взято из Zig и что нет (v0.2) и уроки практики

Основание: Zig для безопасности использует не borrow checker, а **явность и инструменты проверки**: аллокатор передаётся параметром, тестовый аллокатор ловит утечки, `defer` держит очистку рядом с
захватом, ошибки в типе результата. Это ложится на философию Safe Pascal («без форка, без новых синтаксисов, нарушение видно»).

| Идея Zig | Что сделано | Где |
|---|---|---|
| тестовый аллокатор, ловящий утечки | `SafeLiveCount` + `SafeCheckNoLeaks` (R5): счётчик живых объектов под владением, один атомарный инкремент/декремент | §5, R5, `tests/test_safe.pas` |
| `defer` / `errdefer` | `TDefer.Call` / `Cancel`: запись-сторож, срабатывает при выходе из области видимости и при исключении; исключение внутри отложенного вызова не теряется, а учитывается (`SafeDeferFailures`) | §5 |
| аллокатор как явный параметр | правило, без кода: функция, которая создаёт объекты, принимает `TArena` или возвращает `TOwned` (видно, кто отвечает за память) | §4 |
| ошибки как значения | пока `TryX(out V): Boolean`; для функций с несколькими причинами отказа рекомендуется перечисление причин (`TFileError`) вместо Boolean | §0 (идея, без API) |
| переполнение целых = ошибка в безопасном режиме | в FPC это `-Co`; рекомендовано для отладочной сборки (§6) | §6 |
| `comptime`, опции `?T`, срезы без владения | **не берём**: нет в FPC / осознанный отказ (§4) / у нас `String` со счётчиком | |

**Урок практики (порт DOS Navigator, `unxed/dn`).** Замер на настоящем коде (161 файл DN): `New(` 843, `Dispose(` 421, типов `object` 230 против одного `class`, `ShortString`/`String[N]` около 300.
Код в стиле Turbo Pascal (`object`, `New(P, Init(...))`, `Dispose(P, Done)`) концепцией не покрыт: `TOwned<T: class>` не принимает `object`, а затенение `New/Dispose` даёт тысячи
ошибок S1, которые не являются дефектами. Варианты, которые стоит решить до массовой миграции такого кода: (а) расширить Safe Pascal на `object` (владелец над `object`-типом, `Init/Done`);
(б) перевести код на `class`; (в) держать такой слой как `// UNSAFE-UNIT:` с безопасным фасадом. Двоичные форматы файлов, читаемые записями с `String[N]` и `Move`, требуют отдельного
«слоя формата» (§7). Подробнее: `unxed/dn`, `PLAN.md`, раздел «Safe Pascal как стиль кода DN».

## §13. FFI: как cgo, только без cgo

В Go граница с C — это файл с `import "C"`, правила передачи указателей и пара функций
`C.CString`/`C.GoString`. В FPC вызов C уже встроен (`external`, `cdecl`, модуль `ctypes`,
заголовки переводит `h2pas`), поэтому добавлять почти нечего — нужна только граница:

| Go (cgo) | Safe Pascal |
|---|---|
| файл с `import "C"` | модуль обвязки `// UNSAFE-UNIT:` (`*_c.pas` или папка `unsafe/`), в нём все `external` (S12) |
| Go-память в C — только на время вызова, C её не хранит | **F1**: `System.PChar(S)`, `@A[0]` + `Length(A)` из `const`/`var`-параметра — только на время вызова |
| нельзя отдавать C указатели на Go-указатели | **F2**: в C уходят только плоские данные (числа, байты, записи без управляемых полей) |
| `C.CString` + `defer C.free`, `C.GoString` | **F3**: память от C сразу в `TOwned<TCResource>` с парной `free`; C-строка → `String` присваиванием (копия) |
| `//export` + panic не пересекает C | **F4**: обратный вызов `cdecl`; исключение не выпускать в C-кадры (`try..except` внутри) |
| `runtime.LockOSThread` | **F5**: C-библиотеки с привязкой к потоку вызывать из одной задачи; потоки, созданные C, не вызывают Паскаль без инициализации RTL |

API (`safe.pas`): `TCFreeProc = procedure(P: Pointer); cdecl` и `TCResource` (держит указатель и функцию,
освобождает в деструкторе). Образец обвязки — `tests/ffi_libc.pas` (`strlen`, `strdup/free`, `qsort`
с обратным вызовом на Паскале), тест — `tests/test_ffi.pas`.

Доступность: FFI через libc требует динамической сборки (на статическом Linux без libc и на DOS `external 'c'` не линкуется; см. таблицу в §2). Для таких целей обвязка пишется под их собственные библиотеки.

Чего у cgo нет, а у нас есть бесплатно: строки FPC всегда завершаются нулём, поэтому строка
уходит в C **без копии** (`C.CString` в Go копирует всегда); стоимость вызова C — обычный вызов функции.

## §14. Горутины: как в Go, местами лучше

Принцип Go — «делитесь памятью, общаясь» — ложится на модель владения Safe Pascal: в задачу
переходит владение (поля, `Move`), обратно приходят значения по каналу.

| Go | Safe Pascal | Чем лучше или хуже |
|---|---|---|
| `go f(x)` | `G.Go(TF.Create(X))` / `G.Go(@Proc)` | хуже: нет замыканий в FPC 3.2 (в 3.3+ можно добавить перегрузку с анонимной процедурой) |
| `chan T`, `make(chan T, n)` | `specialize TChan<T>`, `TChan.Create(N)`; копия записи — тот же канал | так же: ссылочный тип, `N = 0` — рандеву |
| `v, ok := <-ch`, `for v := range ch` | `Ch.Recv(V)`, `for V in Ch` | так же |
| `select` | `Select([A.Sel, B.Sel], TimeoutMs)` + `TryRecv` | хуже: только приём, не атомарен с приёмом (повторить при неудаче) |
| `sync.WaitGroup`, `errgroup` | `TGroup` | **лучше**: группа ждёт задачи при выходе из области видимости (структурная конкурентность), утечка горутин невозможна |
| panic в горутине убивает процесс | ошибка → отмена группы → `Wait` бросает R7 с исходным текстом | **лучше** |
| `context.Context` | `G.Cancel`, `Done` (закрытый канал) в `Select`, `Cancelled` | так же по смыслу, без лишнего параметра |
| гонки ловит `-race` | гонки предотвращает S11: в задачу — только значения, каналы, `TShared`, `Move` | по-другому: запрет вместо детектора |
| M:N планировщик, миллионы горутин | одна задача = один поток ОС | хуже: тысячи, не миллионы; честно «условные» горутины |

Устройство (переиспользуем RTL, своего минимум): поток — `BeginThread`; замок — `TRTLCriticalSection`;
ожидание — `RTLEvent` (двоичный семафор). Ждущий поток кладёт своё событие в список ожидающих канала,
пока держит его замок, а изменивший состояние будит всех из списка — так пробуждение не теряется
(та же идея, что `sudog` в рантайме Go), а `Select` — это та же регистрация сразу в нескольких каналах.
Строки и динамические массивы FPC считают ссылки атомарно, поэтому значения передаются между потоками как есть.

Менеджер потоков должен инициализироваться раньше SysUtils, поэтому `SafeThreads` стоит первым в `uses`
**файла программы** (одно место на проект). `Safe` не может подключить его сам: модуль, стоящий последним
в `uses`, инициализируется слишком поздно. Без менеджера `Go` бросает R8 с готовой строкой для вставки.
На Linux `SafeThreads` — свои потоки на `clone`/`futex`/`mmap` без libc (§18), с `-dSAFE_LIBC` и на других
Unix — `cthreads`. На DOS (go32v2) потоков нет: `TGroup.Go` бросает R8 сразу.

Ограничения v0.3: `Select` только на приём; нет таймеров (`time.After`) — есть таймаут `Select`;
нет определения взаимоблокировки («all goroutines are asleep»); `TWeak.TryLock` между потоками — гонка (§11).

## §15. Зависимости как в Go, без прокси (план)

В Go модули «просто работают», поэтому чинить нечего: берём модель целиком, теми же словами и теми же
командами, и меняем только то, что у Go держится на инфраструктуре Google (прокси `proxy.golang.org`
и база контрольных сумм `sum.golang.org`). Своей инфраструктуры у нас нет и не будет.

**Что берём без изменений**

| Go | Safe Pascal |
|---|---|
| путь модуля = адрес репозитория, реестра нет | так же: `github.com/acme/json`, `codeberg.org/bob/log`, любой git |
| версия = git-тег `vX.Y.Z` (semver) | так же |
| `go.mod`: `require путь версия` | `deps.txt`, тот же синтаксис (ниже) |
| MVS: из всех требований к модулю берётся **наибольший из минимумов**; без решателя, без сюрпризов, обновление только по команде | так же, тот же алгоритм |
| мажорная версия v2+ — новый путь (`/v2`) | v2+ — **новые имена модулей** (`Acme.Json2`): пространство имён модулей FPC общее на программу, а две мажорные версии должны уживаться в одной программе |
| строка `go 1.22` в `go.mod` | строка `safe 0.4`: какую версию правил этой спеки соблюдает модуль (аналог editions в Rust) |
| `go mod vendor` | `sp vendor` |

```
// deps.txt — в корне приложения и в корне каждой библиотеки
module github.com/me/app
safe 0.4
require github.com/acme/json v1.4.0
require codeberg.org/bob/log v0.3.1
mirror  github.com/acme/json https://codeberg.org/acme-mirror/json    // необязательно
```

**Что меняем: целостность и доступность без прокси**

- **Целостность — сам git.** Git адресует содержимое: хеш коммита однозначно задаёт всё дерево файлов.
  `deps.lock` хранит `путь версия хеш-коммита`; переписанный тег или подменённый репозиторий дают
  несовпадение хеша и ошибку сборки. Отдельная база сумм не нужна. Честная оговорка: первое добавление
  зависимости — доверие при первом использовании (у Go здесь страхует `sum.golang.org`).
- **Доступность — любой экземпляр с тем же хешем равноценен.** Раз содержимое проверяется хешем, «прокси»
  не нужен: подходит любое зеркало. Порядок поиска: локальный кэш → `vendor/` → исходный адрес → строки
  `mirror` → архив Software Heritage (он хранит публичные git-репозитории и находит их по хешу коммита).
  Для приложений рекомендуется `vendor/` в репозитории: тогда сборка работает офлайн и через десять лет.
- **Транспорт — консольный `git`.** Он есть везде; Go в режиме `GOPROXY=direct` делает то же самое.

**Специфика Паскаля**

- Библиотека — это репозиторий с модулями в корне (или в `src/`) и своим `deps.txt`. Сборка добавляет
  `-Fu` на каждую зависимость; для тех, кому нужен вариант «файл рядом» (§2), `sp vendor --flat`
  кладёт модули рядом с исходниками.
- Имена модулей с префиксом владельца (`Acme.Json`; FPC поддерживает имена модулей с точкой),
  иначе две библиотеки с модулем `Json` не соберутся вместе.
- **Аудит unsafe (аналог cargo-geiger, бесплатно).** Метки `// UNSAFE:` и `// UNSAFE-UNIT:` находятся грепом,
  поэтому `sp unsafe` показывает небезопасную поверхность каждой зависимости ещё до того, как её подключили.
  Строка `deny-unsafe github.com/acme/json` в `deps.txt` останавливает сборку, если в новой версии
  зависимости появился unsafe-код.

## §16. Что ещё взять у Go и Rust (план)

### Инструмент `sp`: одна команда, как `go`

Главное удобство Go не в языке, а в одной команде на всё. Каждая подкоманда `sp` — тонкая обёртка над тем,
что уже есть в поставке FPC (проверено: `ptop`, `fpdoc`, `data2inc`, `bin2obj`, `h2pas` ставятся вместе с
`fp-compiler`), поэтому своего кода почти нет:

| `sp` | Аналог | На чём сделано |
|---|---|---|
| `sp build [-release]` | `go build` | `fpc` + `-Fu` зависимостей + профиль проверок (§6): отладка `-Cr -Co -CR -Sa -gh -gt`, релиз без `-Cr -Co -CR` |
| `sp test` | `go test` | обобщённый `tests/run.sh`: `test_*.pas` (код возврата = число провалов) и `compile/*.pas` с `// EXPECT:` (аналог trybuild в Rust); `examples/*.pas` тоже собираются (аналог doc-тестов Rust) |
| `sp vet` | `go vet`, clippy | линтер на `fcl-passrc`: S3–S14 |
| `sp fmt` | `gofmt` | `ptop` с одним зафиксированным конфигом из этого репозитория: один стиль, без настроек |
| `sp doc` | `go doc` | `fpdoc` |
| `sp get / vendor / unsafe` | `go get`, `go mod vendor`, cargo-geiger | §15 |
| `sp embed файлы` | `//go:embed` | `data2inc`: файлы превращаются в модуль с массивами-константами |
| `sp fuzz` | `go test -fuzz` | ниже |

`sp` пишется на самом Safe Pascal одним файлом (зависимости качаются параллельно горутинами §14):
инструмент заодно служит примером проекта.

### Фаззинг почти даром

В C фаззеру нужны санитайзеры, иначе порча памяти остаётся незамеченной. В Safe Pascal ошибка памяти уже
превращена в исключение (`ESafety`, `ERangeError` при `-Cr`, `EAccessViolation`), поэтому достаточно самого
простого фаззера: `fuzz_*.pas` объявляет `procedure Fuzz(const Data: array of Byte)`, `sp fuzz` подаёт
случайные и мутированные входы из папки-корпуса, а вход, вызвавший исключение, сохраняет как новый тест.
Это несколько десятков строк поверх `sp test`.

### Типы-суммы и полный разбор (enum и match из Rust)

Вариантные записи с тегом в Паскале есть с 1970 года. Нет двух проверок, и обе — работа линтера, а не библиотеки:

```pascal
type
  TShapeKind = (skCircle, skRect);
  TShape = record
    Name: String;                      // управляемые поля — в общей части
    case Kind: TShapeKind of
      skCircle: (R: Double);
      skRect:   (W, H: Double);
  end;

function Circle(const AName: String; AR: Double): TShape;   // создаём только так
begin
  Result := Default(TShape); Result.Name := AName; Result.Kind := skCircle; Result.R := AR;
end;

function Area(const S: TShape): Double;
begin
  case S.Kind of                       // все значения перечисления, без else
    skCircle: Result := Pi * S.R * S.R;
    skRect:   Result := S.W * S.H;
  end;
end;
```

- **S13 (полнота).** `case` по перечислению перечисляет все значения и не имеет `else`; при добавлении
  `skTriangle` линтер покажет каждое место, которое надо дописать. FPC 3.2.2 сам об этом не
  предупреждает (проверено).
- **S13 (тег).** Вариантное поле (`S.R`) читается только внутри ветки `case S.Kind of` с его тегом.
- Ошибки остаются исключениями плюс `TryX` (§0); перечисление причин отказа (§12) — это и есть
  `Result<T, E>` без нового типа.

### Неизменяемость по умолчанию (`let` против `let mut`)

**S14:** параметры `const` по умолчанию; `var`/`out` — только когда вызывающий должен увидеть изменение;
константы — `const`, а не переменные, которые никто не меняет. Компилятор уже запрещает запись в
`const`-параметр, а линтер находит параметры без модификатора.

### Что сознательно не берём

| Есть в Go/Rust | Почему не берём |
|---|---|
| borrow checker | без изменения компилятора невозможен; его заменяют правила S5/S11 и рантайм (§4, §8) |
| `?` и `Result<T, E>` | в Паскале исключения с гарантированной финализацией (`TOwned`, `TDefer`) дают то же короче |
| детектор гонок `-race` | гонки предотвращает S11 (в задачу передаётся владение, а не общий доступ) |
| центральный реестр (crates.io), прокси Go | нет инфраструктуры; в модели «хеш + зеркала» (§15) они не нужны |
| M:N планировщик | честно «условные» горутины (§14) |

## §18. Переносимость как в Go: Linux без libc по умолчанию (v0.5)

- **Умолчание на Linux — статический бинарник без libc**: строки — `fpwidestring` + `unicodeducet` (Unicode на Паскале, регистр и сортировка работают даже при `LANG=C`), потоки — `safethreads.pas` (свой менеджер потоков FPC: `clone` + `futex` + `mmap`, как рантайм Go). Один файл работает на любом дистрибутиве: проверено на хосте Ubuntu (glibc) и в chroot Alpine 3.20 (musl); сборка с libc на Alpine не запускается вовсе.
- **Программа с горутинами**: `uses SafeThreads, ...` — ПЕРВЫМ в файле программы (вместо `cthreads`) на всех целях.
- **`-dSAFE_LIBC`** (аналог cgo): `cwstring` + `cthreads`; нужен только для FFI с C-библиотеками. Если libc загружена, а ключа нет, первый `BeginThread` останавливает программу с объяснением (код 232), а не даёт тихую гонку (`tests/compile/mf_libc_guard.pas`).
- Проверено (FPC 3.2.2, кросс-компиляторы собраны из официальных исходников): x86_64 нативно и в Alpine; i386 нативно и под qemu-i386; aarch64 под qemu-aarch64 — `test_safe`, `test_go`, `test_threads` (1500 задач: куча, строки, исключения, рекурсивные замки, `TThread`, события) — 0 провалов, 10 повторов без сбоев.
- Устройство: текущий поток — по указателю стека (регион стека выровнен по своему размеру, в его начале запись потока с threadvar-блоком; главный поток — диапазон `[лимит стека, argv)`), без ассемблера TLS; ассемблер — только `clone` (≈20 строк на архитектуру).
- По мотивам `unxed/static-everywhere`: Safe Pascal по умолчанию — его «Profile S»; `SAFE_LIBC` — «Profile H» (базовая версия glibc = версия на машине сборки). План: в CI — проверка «нет INTERP/NEEDED» (`readelf`) и запуск тестов в контейнерах Alpine/Debian; данные хоста (CA-сертификаты, часовые пояса) читать с хоста, а не вшивать.

**GC — взвешено, не берём.** Для LLM разница с Go — выбор владельца объекта и две «дырки»: циклы `TShared` и заём, переживший владельца. Значения (строки, массивы, записи) и так управляются автоматически. Циклы ловит `SafeCheckNoLeaks` в тестах (R5), висячий заём — отладочная сборка `-gh -CR` + `HEAPTRC=keepreleased` (память не переиспользуется, вызов метода мёртвого объекта ловится). Модель ARC + weak + арены — модель Swift, на ней пишется масса прикладного кода без GC. Трассирующий GC без поддержки компилятора был бы консервативным сканером стеков и кучи (Boehm) — большой unsafe-компонент с недетерминированными деструкторами: оверинжиниринг. Правило по умолчанию для LLM: «не знаешь, что выбрать, — TShared; обратные ссылки — TWeak; деревья и графы — TArena».

## §19. Код в стиле Turbo Pascal (`object`): план

Основание: замер на настоящем коде (DOS Navigator, `unxed/dn`): `New(` 843+103, `Dispose(` 421+39, типов `object` 230+75 против одного `class`, `ShortString`/`String[N]` около 300.
`TOwned<T: class>` такой код не покрывает, а затенение `New/Dispose` даёт тысячи ошибок S1, не являющихся дефектами.

| Вариант | Суть | Решение |
|---|---|---|
| (в) unsafe-слой с безопасным фасадом | старый код помечен `// UNSAFE-UNIT:`, новый пишется по SPEC | **первым**: ноль риска, даёт измерения (счётчик нарушений) |
| (а) расширить Safe Pascal на `object` | владелец над `object`-типом: указатель + «замок времени жизни» с процедурой освобождения (`Done` + `Dispose`); для `object` `New/Dispose` не затенены | **вторым**: узкий прототип на малом срезе, контрольная точка по цифрам |
| (б) перевести код на `class` | `Init/Done` → `Create/Destroy`, ~1400 мест вызова | **запасной**: только для среза, где (а) не дал гарантий |

Порядок (метод RUP: от простого к сложному, атомарные шаги с тестами, на каждом шаге есть что попробовать) и шаги S0–S10 ведутся в `unxed/dn`, `PLAN.md`, раздел «Safe Pascal как стиль кода DN». Лицензия `safe.pas` — MIT.
